**For Dispatcharr 0.33.0.** A fix for a busy loop in Dispatcharr's stream output:

- **A viewer whose channel had no data left could spin a web worker.** When a channel's buffered
  data was gone (most often right after a fallback slate started, while channels were failing
  over), Dispatcharr retried the same position thousands of times a second for seconds on end,
  logging a warning each time (33,090 in one hour on one server) and holding back every other
  stream on that worker. It now waits like any other moment without data.

Install with the one command, as usual.
