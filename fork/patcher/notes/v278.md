**For Dispatcharr 0.33.0.** A fix for a server that ran out of memory:

- **`/api/epg/programs/` could take the whole server down.** Dispatcharr answers it with every
  programme of every guide in one go, ignoring `page_size`; with days of guide history that is
  millions of rows, and one request took a web worker to almost 8 GB in under a minute (the
  page stopped answering). arrTV asks it with `page_size` when its guide request fails. Now a
  request with `page_size` (or `page`) gets one page of at most 1000 of what is still to come, `tvg_id` keeps to that
  guide, and the full list is written out piece by piece instead of built in memory first --
  the same answer as before.

Install with the one command, as usual.
