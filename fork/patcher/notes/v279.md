**For Dispatcharr 0.33.0.** Faster channel starts, and the fix from v278:

- **A provider that refuses every connection no longer slows every channel start.** When an
  account's provider refuses two different streams without sending anything, its streams are
  tried after the other accounts' (still before the "Could Not Dispatch" fallback), once per
  stream instead of three times with waits in between, until it sends data again or for 10
  minutes. Starts that waited about 12 seconds for refusals now start on the account that works.
  Only on accounts with Channel Switch Overlap on; the switch log shows when it happens.
- **`/api/epg/programs/` could take the whole server down** (v278, never published on its own):
  a request with `page_size` (or `page`) now gets one page of at most 1000 of what is still to
  come, `tvg_id` keeps to that guide, and the full list is written out piece by piece instead of
  built in memory first -- the same answer as before.

Install with the one command, as usual.
