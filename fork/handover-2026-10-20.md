## 2. Dispatch More v275 (since v274)

Commits `dbc08c86`, `a0ce4195`, `952bb6c0`.

1. **The `guides` stamp counts only the login's own guides** (`apps/proxy/live_proxy/app_sync.py`).
   Before, a refresh of any of the server's 43 EPG sources (several an hour) moved it, and arrTV
   downloaded the whole 24 h grid (41,000 programmes, 16 MB) each time. `sources` in the
   `app-sync` answer now lists only the sources the login's guides come from.
2. **`GET /api/core/app-guide-marks/`** -> `{"guides": <stamp>, "marks": {"<epg id>": "<8 hex>"|"0"}}`:
   one mark per guide of the login's channels, `sha1("count:max id")[:8]` from one grouped query
   (`guide_marks`), kept in the 10 s answer cache with the sync answer (`marks_for`). `"0"` = no
   programmes.
3. **`/api/epg/grid/?epg_ids=1,2,3`** (`apps/epg/api_grid.py`, `_parse_epg_ids`, applied after
   `_partition_visible_channels`, so a login still sees only its own channels): only those guides;
   dummy-guide channels with other guides and channels without a guide are left out; `epg_ids=`
   empty gives nothing. Without the parameter the grid is unchanged.
4. **`/api/epg/grid/?categories=1`** (`_parse_categories`): each stored programme also carries
   `categories` from `custom_properties` (`[]` when none). Without it the grid is byte for byte
   stock. arrTV used to ask `/api/epg/programs/<id>/` once per airing programme for the tints.
5. Capabilities (`app_devices.capabilities`): `guide_marks_url`, `grid_epg_ids: true`,
   `grid_categories: true`.
6. Tests in `apps/proxy/live_proxy/tests/test_app_sync.py`: unused source refresh moves nothing,
   a re-imported guide moves its own mark only, marks cover exactly the lineup's guides, marks
   stamp = sync stamp, capabilities, grid `epg_ids` filter, grid categories only when asked.
7. Docs: contract §1a (the endpoints, how to use them), HANDOVER §5.11 and the release line,
   `guide-loading-plan.md` status, CLAUDE.md "v275 is the latest".

Considered and **dropped**: a `guide_past_days` capability. On Dispatcharr 0.30+ (the user runs
0.31) arrTV already takes look-back history from the grid (`extendGridWindowInBackground`); the
43 upstream XMLTV feeds (`layerUpstreamInBackground`) are only read on servers older than 0.30.
The earlier claim "the app downloads 43 feeds for look-back" was wrong for this server.

### How a guide update decides what to fetch now

1. `app-sync` stamp **same** -> nothing (cache < 12 h old).
2. Stamp **changed** and marks saved for that cache -> `app-guide-marks`; the guides whose mark
   moved or that are new -> `grid?epg_ids=...&categories=1` over now-1 h..end of Guide Days ->
   written for every channel those rows reach -> marks saved once written.
3. More than 400 changed guides or more than a third of them, no saved marks, or a server before
   v275 -> the whole grid as before.
4. Marks are saved after a full download only when the marks' stamp equals the stamp the download
   started from (a change during the download is not covered up), and when the guide is found
   unchanged (`ensureMarks`, so caches from before v275 get marks without a download).
