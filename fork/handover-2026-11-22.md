## 3. What 0.34 brings that touches the fork (from the changelog; checked in the code in §4)

- **Proxy:** Max Connection Attempts (`max_retries`, 1-10) and Stream Retry Timeout
  (`stream_retry_timeout`, 0-30 s) configurable (#1600, the issue next to the user's #1694);
  HEAD on live stream URLs answers the container without starting a stream (#1731, Jellyfin's
  probe); buffering-timeout failover keeps the stable-connection reset (#1965) and retries once per
  timeout (#1900); `fetch_chunk` and the relay pipes non-blocking (#1897, worker deadlocks);
  channel events use the override-aware name.
- **HDHR:** its own output format (defaults to MPEG-TS: a behaviour change).
- **Stream info:** `audio_streams` (every track with language) in Redis and `Stream.stream_stats`;
  probes write the database once per quiet probe.
- **Output profiles and fMP4:** restart at a PMT/ES layout change or a source discontinuity.
- **Security:** `X-Forwarded-For` read before `X-Real-IP`; `/me` cannot change admin-managed access;
  credentials masked in container logs (a setting); SSRF-safe fetches pin the IP.
- **M3U:** stale-stream cleanup with `select_for_update` + `_raw_delete`; catch-up rollup in one
  statement; stream URLs up to 8192.
- **EPG:** programme channel ids trimmed; XMLTV with trailing comments accepted; series-rule regex.
- **VOD:** a bare-URL seek resumes the viewer's session.
- **Plugins:** capabilities with approval, async actions, persistent services, code/data dirs.
- **Dependencies:** Django 6.0.10, celery 5.7.0, **redis-py 8.1.0**, torch 2.15.0, sentence-transformers 6.3.0.
- **Installer (Debian):** UTF-8 locale for the units and uWSGI; nginx `uwsgi_buffer_size 16k`.

- `input/buffer.py`: `get_chunks` and `get_chunks_exact` **removed**, replaced by

### 4.3 VOD proxy, proxy utils (read)

- `vod_proxy/views.py`: a bare URL (no session id) resumes the viewer's own session, matched on
  content + user + address + user agent; an idle one at once, a running one waited for up to
  `SESSION_SETTLE_SECONDS`; HEAD never waits. The fork's `app_one_device.check_request` sits after
  this and still sees every streaming request (a resumed one comes back with its session id).
- `proxy/utils.py`: viewer limits skip idle VOD sessions and the request's own session;
  `user_limit_evicts_oldest_stream`.
- **R3 (an old fork bug, not 0.34's)**: Stream Check's `_Providers._look` decides whether anything
  plays from `live:channel:*:metadata` and **`vod_proxy:connection:*`**. The VOD proxy writes
  `vod_persistent_connection:<session>`; `vod_proxy:connection:*` comes from the legacy
  `create_connection` (multi_worker_connection_manager.py ~2050) that nothing calls. So a movie or
  episode playing is never seen: with only-when-idle the check runs during VOD, and
  `in_use(provider)` returns False for everything when only VOD plays -- the check can take the
  connection of a provider a VOD viewer is on. Same in 0.33.
