## 6. Installing and uninstalling across Dispatcharr versions

### 6.1 What was wrong (every release up to v275)

`debian_install.sh` updates an existing install with `git fetch; git reset --hard HEAD; git
checkout $DISPATCH_BRANCH; git pull` (then pip, migrate, `npm run build`). After that every file a
release *replaced* is the new version's stock file, while the files it *added* and
`.fork-install.json` (untracked) stay. Then:

- the next `install.sh` saw the record, "took the older release off first", and `patch.py uninstall`
  copied the backup -- **the old version's originals** -- over the new Dispatcharr (0.31.0's files
  over 0.33.0: a broken Dispatcharr);
- the uninstaller the old release left in `/var/lib/dispatch-more/` does the same, and it is what
  `sudo bash /var/lib/dispatch-more/uninstall.sh` and the page's watcher run.

Docker was not affected (a new image's `/app` has no record; the old release refuses the new
version and the container starts stock).

### 6.2 What the patcher does now (`fc58dc23`)

`fork/patcher/patch.py`, `uninstall()`:
- `updated` = the record's `for_dispatcharr` differs from the `version.py` found now;
- a **replaced** file is restored from the backup only while the file there is the release's
  (`sha256` from the manifest), or missing; otherwise left and listed;
- a **removed** file is restored only while it is still absent;
- an **added** file is deleted only while it is the release's; otherwise left and listed;
- the **frontend** (`frontend/dist`) is put back only while it is the release's: the manifest has a
  new `frontend_sha256` (of the built `index.html`, whose asset names are content hashes; written
  by `build-overlay.sh`); for manifests without it (v275 and older) only when the version is
  unchanged;
- when it is, **collectstatic's copies** of the release's frontend in `static/` go with it
  (`unstatic_frontend`, second session, §8.4): each file of the release's `frontend/dist` whose
  copy in `static/` is still byte for byte the release's becomes stock's file of that name, or is
  deleted when stock has none (empty folders too); anything else in `static/` is left;
- what was left is printed ("N file(s) were left as they are: Dispatcharr was updated from X to Y
  since" / "something else has changed them since"); files restored across a version change are
  listed with a warning;
- `install()` says "Dispatcharr was updated from X to Y under it: only what is still vNN's is taken
  off" before its quiet uninstall of the older release.

A side effect, on purpose: a fork file edited by hand after installing is now **kept** by uninstall
(it used to be overwritten), and the next install refuses it as "not stock" (exit 4).

`fork/patcher/quick-install.sh`:
- `--uninstall` (`curl ... | sudo bash -s -- --uninstall`): needs `$STATE/manifest.json`; downloads
  the newest release (any Dispatcharr version; or `DISPATCH_MORE_ARCHIVE`), copies its scripts
  (patch.py, uninstall.sh, install.sh, docker-entrypoint.sh, dvr-worker.sh, captions.sh,
  memory-recorder.sh -- **never the manifest**) into the state folder and runs `uninstall.sh`
  (Docker: `--docker`, then touches `$STATE/uninstalled` so the entrypoint stays stock, and says to
  restart). The **safe way off for anyone on v275 or older whose Dispatcharr was updated**.
- When no release exists for the Dispatcharr found and `$STATE/record.json` exists, it says the old
  release is still recorded and prints the `--uninstall` command.
- Unknown options are refused.

### 6.3 What is checked (`test-patcher.sh`, new parts)

- "A file changed after installing": an added and a replaced file edited -> uninstall keeps both,
  says so, everything else stock.
- **U** (`UPDATED_TO=<newer version>`): this release on X, `dispatcharr_update` (emulates
  `debian_install.sh`: delete what X had and Y has not, copy Y's tracked files over, new frontend),
  `quick-install.sh --uninstall` -> **stock Y byte for byte**. With **v275's own** patch.py it fails
  (checked: that is the bug); with the new scripts it passes.
- **P** (`PREVIOUS_ARCHIVE=<release for an older Dispatcharr>`): the older release on X, updated to
  Y, this release over it (must say "updated from X to Y"), every file the release's, uninstalled ->
  **stock Y byte for byte, nothing of the older release left**.
- `release.sh` sets both by itself: `UPDATED_TO` = newest local x.y.z tag above the base version
  (none now: 0.33.0 is the newest), `PREVIOUS_ARCHIVE` = newest `out/` archive for another
  Dispatcharr version (v275's).
